# 按需分支

只读当前情形相关的行，不把全部问题依次问用户。

## 输入和要求

| 情形 | 下一步 |
|---|---|
| 只有视频，没有想法或参考图 | 先理解内容，提出适合的视觉表达与设计建议；参考图不是开工前置条件。 |
| 用户只说“先理解视频” | 给内容、看点、证据范围和必要的不确定点，停在理解阶段。 |
| 视频附带完整设计要求 | 检查是否与视频内容冲突，沿要求执行；无需重新让用户选同一方向。 |
| 有零散要求 | 先保留确定部分，再补会影响主题、主体、硬性文字和交付的缺口。其余给建议。 |
| 同时出现“不要文字”和“必须放完整标题”等冲突 | 集中提出冲突，问清优先级；若后一条明确在修改前一条，直接按新要求。 |
| 原视频无字幕、音频不清或部分不可读 | 先使用当前可读画面、音轨、已有转写等；说明范围。能继续做的先做，只有核心意义无法确定时才请求所缺信息。 |
| 多个视频或多个候选人物且无法判断目标 | 先查看可用素材，仍存在会改变封面主体的歧义时问一次；不任选一个后宣称已确认。 |
| 用户指定人物必须出现 | 使用本次人物参考，保证身份可辨；可重设动作与眼神来建立场景关系。 |
| 用户指定不出镜或只展示产品/作品 | 围绕物件、结果或场景组织画面；先前视频出现过本人不构成这次出镜要求。 |
| 没有账号名、Logo 或固定视觉规范 | 不虚构署名和标识；在小样中建议 1–2 个识别元素，由用户认可后再记录。 |

## 视频类型决定视觉核心

以下是选择依据，不是固定模板；混合类型可以组合。

| 类型 | 优先寻找的看点与素材 | 常见的错误承诺 |
|---|---|---|
| 口播观点、评论、避坑 | 核心判断、观众疑问、人物态度、能表达关系的场景或隐喻 | 将观点包装为本人已实测的收益、权威统计或完整教程 |
| 教程、屏幕操作 | 做成的结果、具体用途、关键操作对象、前后变化 | 展示视频没有做到的成品或把软件界面文字堆满封面 |
| 产品/实物展示 | 产品本体、真实使用场景、已展示的特征、人与物的关系 | 生成画面改变产品结构、规格或夸大视频未展示的效果 |
| 故事、剧情、漫剧作品 | 人物关系、悬念、冲突瞬间、场景和情绪 | 剧透关键结局，或制作与作品无关的角色和剧情 |
| 生活记录、旅行、体验 | 具体地点、事件、感受、人与环境的关系 | 强行做副业收益、教程结果或收入反差 |
| 成果、改造、前后对比 | 真实前后素材、同一对象与可比较视角 | 伪造“之前”状态、大小比例或未实现的结果 |

## 选择、修改和续接

| 用户反馈 | 响应方式 |
|---|---|
| 已选内容角度 | 直接针对该角度出视觉小样，不重新解释同一轮角度。 |
| 所有方向都不喜欢 | 保留内容事实和硬性要求，简短定位主要问题；反馈足够具体则直接重做方向。 |
| 喜欢 A 的构图、C 的人物表现 | 合并为一张新预览，说明保留和替换的部分，不把所有小样重做一遍。 |
| 只换一个词、改表情、换背景等局部调整 | 以当前认可图为目标做针对性编辑，冻结其余认可元素；检查修改是否引起连带变化。 |
| 修改需求会连带影响已认可布局 | 说明实际取舍，先完成可保留的部分；确有无法同时满足的冲突再问。 |
| 已认可且没有修改 | 检查后交付认可图；不要再索要同义确认或自动重新生成“高级版”。 |
| 已交付后再改 | 新建版本保留原件，使用最新有效要求；同一方案不重复全套视频理解。 |
| 本次只需要一个平台/一个规格 | 仅交付指定结果，覆盖双平台默认。 |
| 两平台可共用同一画幅 | 可以同图分别命名，明确同画面；需要不同裁切或布局时才做对应适配并预览。 |

## 能力不足

- 生图尚未调用：先区分“找到工具”和“取得生成输出”。按宿主契约实际调用，不能将未尝试说成不可用，也不能把截图叠字当作已经实现的新场景。
- 生图不可用或有明确调用失败：先完成能完成的理解、需求整理和具体方案；说明缺少哪项出图能力及对当前画面的影响，不以文字或程序占位图冒充已完成小样。若宿主工具要求用户选择其他生成渠道，遵守其要求；用户已指定可用渠道时直接沿指定渠道。简化实拍是可供用户选择的替代方向，不是静默降级。
- 理解工具缺少默认模型或认证失效：不为了读视频改全局模型、轮换凭证或切换账号。可先使用本地元数据、关键帧、字幕与现有音频能力；需要用户动作时准确说明缺什么。
- 素材太大：先在项目内制作分析副本或抽取音频/帧，保留原件；不要让用户无故重复上传，也不要把抽帧范围夸大成完整读取。
- 一次失败后根据错误修正相关原因；缺少凭证、文件或能力时，停住依赖它的步骤并继续独立工作，避免无上限重试和扩展任务。
