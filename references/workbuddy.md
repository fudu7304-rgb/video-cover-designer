# WorkBuddy 宿主适配

## 发现能力与实际执行

先通过当前宿主的 `ToolSearch` 搜索图像生成/编辑能力，读取实际返回的 `ImageGen` 说明与参数 schema。找到工具只代表能力可发现；必须实际调用并取得生成图片，才能说已完成生图。不能根据工具名、聊天模型名或搜索成功推断已经生成。

当工具合同指定通过 `DeferExecuteTool` 执行 `ImageGen` 时，按该合同组织调用。`params` 只包含当次 schema 明示的字段、类型和允许值；必填项、模型选择和输出方式都以当次结果为准，不猜模型名或补写不存在的参数。

- 本人需要出现时，先实际查看清晰的本地人物参考，再按 schema 要求传入 `image1`，用于保留身份。宿主若要求附件或文件标识，先取得真实可用的标识，不编造路径、URL 或附件 ID。
- `image2`、`image3` 仅在确需额外身份、风格或编辑参考时使用，并说明各自作用；不为凑参数重复传图。
- 不套用 Codex 的 `referenced_image_paths`、`num_last_images_to_include` 等参数。不同宿主字段不能混用，只认当前 WorkBuddy 工具合同。
- 参数错误先对照返回的 schema 修正；调用失败不算已生成，也不能用搜索记录充当执行记录。

## 积分说明与已有授权

遵守当次工具合同对额外积分、预计用量和调用前提示的要求。此前一次合同曾提示约 **5–10 积分/图**；这是历史信息，不是永久报价，不能直接用于当前估价。当前合同未给价格时，不编造数字。

本次若要生成多张，按当前合同说明张数与可确定的积分信息。已有授权覆盖本次制作时，告知后继续执行；只有宿主明确要求额外授权且现有授权不足时，才取得必要授权，不自行增加逐图审批。工具只要求告知费用时，不把告知变成重复确认。不得绕过宿主的真实费用限制或为避开提示而偷偷换成截图叠字。

## 最小执行条件示例

以“本人置身主题场景”的封面任务为例，至少落实：

1. 当前 `ToolSearch` 返回了可执行的 `ImageGen` 合同，所需参数与授权条件已满足。
2. 已打开并确认一张可用的本地人物参考，按要求提供给 `image1`。
3. 已明确场景、人物动作、主题物件及其关系、标题与留白位置，并将这些设计写入 schema 接受的描述字段；不只写“高级、好看”。
4. 通过当前合同要求的执行入口实际调用工具，保存真实返回图片、有效提示词和使用的参考来源。
5. 逐张打开生成图片验收，再展示给用户；返回成功或文件存在不代替看图。

中文生成不稳定时，可以先生成预留标题空间的场景，再用可用排版能力精确叠加中文，最后检查完整合成图。精确叠字是后续制作步骤，不能替代已经承诺的场景设计。

验收重点：人物身份可辨，动作和肢体自然，主体与主题物件形成可见关系，标题准确且层次清楚，缩图仍能读懂核心；多张小样须有真实构图区别。未达到要求时修正具体问题，不直接宣布完成。

确实没有可用生成/编辑能力，或必要条件无法满足时，说明实际缺口并停在具体方案。任务要求场景设计时，不能把原视频截图叠字、占位图或普通排版稿冒充已完成的场景小样。若用户另行选择截图排版路线，则明确按该路线制作与验收。
