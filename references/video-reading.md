# 读取视频与内容证据

先使用宿主已提供的可靠视频理解能力；本地文件可通过 ffprobe、ffmpeg 与脚本辅助。工具输出仍需与画面和字幕核对。

## 本地检查助手

依赖：Python 3、Pillow、可执行的 ffmpeg 和 ffprobe。缺少依赖时先检查宿主捆绑运行时或已安装工具，按实际环境调用；不要把某台机器的 Python 绝对路径写入 skill。

```text
python scripts/inspect_video.py "视频文件.mp4" --out "项目/analysis-01"
python scripts/inspect_video.py "视频文件.mp4" --out "项目/analysis-02" --samples 8 --audio
python scripts/inspect_video.py "视频文件.mp4" --out "项目/analysis-detail" --at 0 12.5 48 90 --font "字体文件.ttf"
```

从 skill 所在目录执行，或使用脚本绝对路径。输出目录须为新目录或空目录；续查使用新目录，避免覆盖已采集证据。脚本默认均匀取样，输出元数据、带时间点帧、联系表和帧清单；`--audio` 额外提取完整单声道 16 kHz WAV。

脚本只采集证据，不转写、不做语义总结、不自动定位字幕、不调用模型。均匀帧适合了解整体画面；针对场景变化、人物特写和内容转折追加取样。

## 获取内容

1. 看全时长与取样分布，判断是口播、演示、实拍、作品还是混合内容。长视频先建立章节，再深入影响封面的片段，不只看开头。
2. 优先取得清晰音轨或已有字幕/口播稿。可用现成转写能力时使用其已授权配置；没有转写能力但字幕覆盖足够时逐段读字幕，并说明实际依据。
3. 字幕在画面内时，先检查实际位置、语言与覆盖范围，再选适合的密度读取。不同视频位置和排版不同，不固定裁切画面下方某个百分比。快速切换的字幕与短暂关键帧需要更密集取样。
4. 转写、OCR 与原图不一致时回到原视频核对。金额、人名、工具名与结论中的否定词尤其需要注意；不清楚的数字不用于确定文案承诺。
5. 图像模型需要人物身份参考时，从原视频提取几张清晰、正面或自然侧面的参考，实际查看后再传给生成工具。避免用严重运动模糊或遮挡的帧作为唯一身份依据。

## 内容理解的输出

简短交付以下信息，不强制固定标题或长篇转写：

- 主题与观众：明确视频对象；推断的受众标为判断。
- 核心看点：一个最有价值的观看理由，以及视频确实支持的内容承诺。
- 关键逻辑与时间点：足以解释封面方向的内容链。
- 可用视觉：人物、物件、实际结果、作品、场景及需要生成/合成的部分。
- 真正影响设计的不确定点，以及下一步建议。

讲述者的观点、引用他人的话、亲身实测与有证据的事实要区分。理解用户视频本身不需要为每个观点查外网；若封面要添加外部事实、最新平台规格或精确引用，再查相应来源。不要把“制作方便”自动写成“保证赚钱”，也不要把这条案例的避坑主题迁移给无关视频。

## 分析副本

大素材可在项目内生成较小的分析副本，保留声音和足够辨认画面的分辨率。低帧率副本适合静态口播初查，涉及动作、转场、演示细节时需回到原帧率片段。分辨率和采样密度按内容决定，不固定每段视频为本案例的 540×960、2 fps。

只给出了部分片段、画面帧或字幕时，不声称完整观看或听完视频。可读内容足够支撑设计就继续，关键意义缺失则补问；不要求用户提供工具已经能读取的同一文件。
