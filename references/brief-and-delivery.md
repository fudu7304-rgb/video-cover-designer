# 方案、修改与交付记录

记录放在当次项目目录，避免把个人视频、人物参考和本次要求写进安装目录或长期默认。文件结构随任务规模选择，不必每次创建完整目录树。

## 最小任务记录

保留足以续接工作的内容：

- 视频/参考来源与实际读取范围，重要帧时间点。
- 当前阶段与最新用户要求；确认项、设计建议和关键待定项。
- 本次内容角度、封面承诺、精确文案、必须出现/禁止改变的元素。
- 人物出镜与身份要求；哪些画面来自视频，哪些为辅助生成。
- 平台与输出规格及其依据。
- 小样编号、图片路径、生成/编辑提示词、用户选择与修改反馈。
- 最新认可图路径和获认可的内容；交付路径与必要验证。

用户更正信息时更新有效状态，保留必要历史以免改回旧要求。不要将设计者暂用的配色或署名记为用户确认。

## 方案预览

用实际图片配简短说明，让用户能判断最终文案、构图、人物、背景和整体气质。可以用一个问题收集选择或修改，例如“更喜欢 A、B 还是 C？也可以组合”。不把每个字体、字号、颜色都变成单独审批点。

若用户只确认了内容角度，仍需视觉小样；若确认了完整视觉小样并表示无修改，就不需要再次提交同一文字方案等确认。

## 修改与版本

局部编辑要写清“改变什么”和“保持什么”，以最新认可图片作为编辑目标。查看修改后结果，防止脸型、标题、手部或构图发生无意变化。原件保留，用 v2 等新文件名保存修订稿。

用户反馈笼统时，结合预览指出一两个最可能的问题并补问；反馈足够清楚时直接执行，不重复整套问卷。大方向被否决时返回构图或内容角度，保留仍有效的要求。

## 定稿质量

按本图实际内容检查，不机械列出无关检查项：

- 文案：精确拼写、数字、否定词、语义与视频一致；没有误导性的观看承诺。
- 人物/物件：身份可辨、神态与肢体自然、实物结构和关键特征完整。
- 视觉关系：道具、场景与人物行为能表达主题；需要缩小才能使用的封面，缩小后仍可辨认核心。
- 平台输出：像素、比例、格式、体积和实际裁切符合已知入口；不将视频画幅自动等同于封面展示画幅。
- 文件：能打开、保存到用户项目；认可图原样交付时可核对哈希；派生版有清晰用途。

检查是发现实际问题的手段，不是自动美化人物、重新生成或新增审批的理由。

## 原样交付助手

`scripts/finalize_cover.py` 只做原样复制、哈希核对、清单和 ZIP 打包，不生成、不裁切、不放大、不改图。需要不同布局时先按宿主图像编辑规范制作并认可对应图片，再交给助手。

```text
python scripts/finalize_cover.py --out "项目/final-v1" --cover "douyin=项目/认可图.png" --cover "xiaohongshu=项目/认可图.png"
python scripts/finalize_cover.py --out "项目/final-v2" --cover "douyin=项目/抖音适配.png" --cover "xiaohongshu=项目/小红书适配.png"
```

输出目录必须新建或为空。多个标签可以引用同一图，交付清单会说明是否同图；不能把复制后改文件名称为不同构图。

交付时给成品图片或当前宿主已显示的预览、可点击下载路径、实际尺寸/比例和简短适用说明。未在用户发布入口实测的内容，不宣称已上传验证或所有展示位置都不会裁切。完整提示词保存在文件中供用户查看，不必把长提示词粘满回复。
