# 制作路线与看图验收

小样的作用是让用户选择实际画面。先把视觉想法做出来，再比较哪张最适合这条视频；文件存在或文字无错字，只说明交付的一部分成立。

## 从画面需要选择工具

每张小样先用一两句话确定：主体及状态/动作、主体与其他物件/环境的关系、核心视觉看点、文字位置。它是制作依据，不额外增加一次用户审批，也不用先列出所有字体字号。

| 画面需要 | 合适的制作方式 |
|---|---|
| 用户选择简洁实拍，或原帧已有合适动作、环境与情绪 | 选清晰帧，裁切、调色、必要修图并排版。以原画面的表现力为依据。 |
| 人物需要视频中没有的动作/眼神，或需要新的场景、AI 辅助画面、视觉隐喻 | 用可接收参考图的图像生成/编辑工具，或能实现该场景的合成工具实际制作；人物参考用于保留身份。不能以抠图贴字替代尚未实现的主体互动。 |
| 真实产品、界面、数据或前后对比必须准确 | 保留对应实拍/截图的关键特征，只生成允许变化的背景或辅助元素；不伪造结构、数据或结果。 |
| 只修改认可图的一个词或局部细节 | 以最新认可图为目标，选择能保留其余内容的编辑方式；不从头重新设计。 |

遵守宿主对生成、编辑、引用图和后期处理的要求。有多种工具时选能保留参考身份、实现构图且可查看输出的能力，不把某个聊天模型或生图模型写成固定前提。人物参考、风格参考、编辑目标的作用要明确，不能只在提示词中写“是本人”却不输入可用身份参考。工具无法接收参考时，先确认是否有可用的参考编辑/合成路线；不能保证身份时说明限制，不把陌生人当作本人交付。

中文需要精确排版时，可以先生成完整人物与场景并留出文字空间，再用允许的排版工具加字。`ffmpeg`、Pillow 或 SVG 的文字叠加能辅助排版；它们不会自动完成新场景与人物关系。`inspect_video.py` 只提取分析素材，`finalize_cover.py` 只原样交付，均不是生图工具。

## 让小样真正可比较

2–3 张默认小样应体现实质选择，例如人物身处场景、人与物互动、以结果物件为主等不同表达；按视频选用，不固定套这三类。可共用身份参考和文案，但应改变足以影响观看感受的构图、动作、空间关系或隐喻。

同一人物帧配不同标题、背景色或底栏，属于文案/样式变体；用户只要此类对比时可以提供并如实命名，不能当成默认的不同视觉方案。不要把三种标题各复制到相同大头照上，再用说明文字声称它们分别是“场景”“对比”和“故事”。

## 逐图验收

必须实际查看输出图片；在原尺寸检查细节，再以手机列表中接近实际展示的缩图检查层级。没有预览能力时说明尚未完成视觉验收，不宣称已经看过。

1. **承诺有没有画出来。** 对照制作依据，检查主体、关键道具、动作和场景关系是否可见。例如方案用“闭卷/开卷”表达工具能力差异，画面应通过书本、检索资料或人物行为形成区别，不能只把这四个字写在相同照片上。例子不构成其他视频的默认模板。
2. **画面能否自己表达看点。** 暂时忽略文字，检查能否感受到方案承诺的关系、变化或情绪；无需靠无字画面完整讲清所有概念。用户认可的文字主导实拍风格按其目标验收。
3. **视觉是否完整。** 检查人物身份与肢体、抠图边缘、光线透视、人与道具接触、留白和元素主次；避免粗糙粘贴、无意义装饰、拥挤色块或遮挡主体。装饰应帮助表达内容。
4. **文字与缩图是否成立。** 标题有重点、行数和长度适合画面；小字不承担必须读懂的关键信息，文字不挤压脸和关键物件。与视频事实、最终文案及输出规格一致。
5. **小样间是否有选择价值。** 并排检查是否只是同帧换字/换色；若是，补做真正不同的视觉表达，或按用户要求明确标为样式变体。

发现缺陷就针对该问题修正，并重新查看受影响的部分。若缺少关键场景，回到场景制作；若只有错字，修字即可。不要用长篇设计理由掩盖图中没有的内容，也不要以验收为由擅自推翻已认可图。

## 能力与记录

搜索到工具、写好提示词、生成任务已提交、输出可查看，是不同状态。记录实际使用的工具、参考作用、输出路径和未解决问题；没有调用或失败时如实标明。生成不可用且当前方案依赖它时，按 [能力不足分支](branches.md#能力不足) 处理。可以提出简化实拍替代方案，让用户选择，不能悄悄改变已选表达。
